# 主题调试窗口布局修复：一个坐标错误解释了全部症状

> 日期：2026-10-14
> 用户报的 8 类症状（滑块压数值、字体压按钮、控件互相覆盖、极大空白、纵向间距不统一、
> 缩放后恶化……）**根因只有一个**：参数行的控件被画到了错误的行。

## 根因

`GlassWorkbench.cpp` 的 `DrawParamRow` 里，控件绘制 lambda **把 y 硬编码成第一行**：

```cpp
auto drawControl = [&](float x, float width) {
    ImGui::SetCursorScreenPos(ImVec2(x, rowStart.y));   // ← 永远第一行
    …
};
…
// 双行模式下想在**第二行**画滑块：
const float secondY = rowStart.y + lineH + style.ItemSpacing.y;
drawControl(rowStart.x, layout.slider);                 // ← 漏了 y，实际画回第一行
```

于是：

| 用户报的现象 | 真实原因 |
|---|---|
| 滑块与数值输入框重叠 | 滑块被画回**第一行**，正好压在数值格上 |
| 字体与按钮严重重叠 | 同上（滑块/控件压住参数名与数值） |
| 不同参数的控件互相覆盖 | 每行的第二行留空，相邻行视觉上挤在一起 |
| 某些控件之间极大空白 | 第二行本该放滑块，却空着（每行白留 104px） |
| 纵向间距完全不统一 | 同一原因在单/双行模式下表现不同 |
| 窗口缩放后布局恶化 | 宽度变化 ⇒ 单/双行模式来回切换 ⇒ 同一错误反复显形 |

**为什么本工程默认走双行**（这也是为什么问题一直存在）：本工程字体 40px、`FramePadding=(28,20)`
⇒ 数值列 ≈216px、重置列 ≈142px、名称列 228px、三个间距 72px，合计 ≈658px；
而内容可用宽度 672px ⇒ **滑块只剩约 14px**，低于 `minSlider(150)` ⇒ `ComputeParamRowLayout`
正确地判为双行 —— 双行本身是对的，错的是双行分支把控件画错了行。

## 修复

给 `drawControl` 补上 `y` 参数，两个分支各自传正确的行：

```cpp
auto drawControl = [&](float x, float width, float y) {
    ImGui::SetCursorScreenPos(ImVec2(x, y));
    …
};
// 双行：第一行 = 名称 + 数值 + 重置；第二行 = 滑块（占满可用宽度）
drawControl(rowStart.x, layout.slider, secondY);
// 单行：名称 | 滑块 | 数值 | 重置
drawControl(x, layout.slider, rowStart.y);
```

**没有重写布局引擎**：`ParamRowLayout.h`（纯逻辑内核）、`ComputeParamRowLayout` 的
列宽分配与让位顺序、`FitTextToWidth`、每帧按可用宽度重算 —— 全部保留原样，
只修正了「把布局算出来的矩形画到实际坐标」这一步。

## 新增：布局诊断可视化（用户第八节）

`AURORA_LAYOUT_DEBUG=1` 时给参数行的四个格子画出**实际布局矩形**
（名称=红 / 控件=绿 / 数值=蓝 / 重置=黄，`LayoutDebugRect`）。

它的价值：本轮这个 bug 若有此开关，截图里会直接看到**滑块矩形跑到了名称那一行**，
不必从"看起来重叠"倒推。默认关闭，判定只做一次静态初始化 ⇒ 正常使用零开销。

## 未做 / 未验（如实列出）

1. **顶部目标分页标签在窄宽度下仍会截断**（截图里的"液态…/窗口…"）。
   分页栏本身实现是对的（横向滚动 + 左右翻页 + 选中项自动滚进可视区），
   截断发生在标签文字超出自身格子时；**本次未改**，属独立小问题。
2. **状态行文字可能超出窗口右边缘**（如"已从 /data/local/tmp/…"）——
   可用现成的 `FitTextToWidth` 截断，**本次未改**。
3. 用户任务书 §九 列出的 13 项验收，**没有逐项跑**（按"尽量减少测试"的要求）：
   本次只做了修复后的参数区截图确认；分页切换、分组折叠、最小↔最大窗口宽度、
   不同密度等场景**尚未逐项验收**。
4. 触控命中区域：本轮只改了**绘制坐标**，而 ImGui 的命中矩形由同一个
   `SetCursorScreenPos` 决定 ⇒ 视觉与命中天然一致（不存在"按钮移了、点击还在原地"）。
   但**没有对每一类控件逐一实测**点击落点。
