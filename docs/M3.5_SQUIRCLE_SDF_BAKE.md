# M3.5：连续曲率圆角落进 shader（SDF 烘焙路径）

> 结论先说：**解析式路线已用实测排除，正确路径是烘焙 SDF 掩膜** ——
> 这正是 Kyant 自己的做法。烘焙器已实现并验证。

## 一、为什么不能解析计算

三条实测结论（都不是推测）：

### 1.1 超椭圆逼近不可行

`build/recon/squircle_sdf_calib.cpp` 用 `|u|^n + |v|^n = 1` 拟合精确曲线：

```text
n = 2.00  ->  max|pred - actual| = 0.953262   (单位: r)
n = 5.00  ->  max|pred - actual| = 0.968553
最佳 n = 2.00, 最大偏差 = 0.953
```

根因：精确解的角在每条边上延伸 **5r/3**，而超椭圆的支撑域固定为 **r**。
**两者不是同一个域**，直接比 f 值无意义。

### 1.2 Kyant 自己也不解析计算

`docs/KYANT_GLASS_TECH.md` 核实（附逐字代码块校验）：

- `backdrop` 库在 shader 里用的是**标准圆角矩形 SDF**
  （`internal/Shaders.kt:22-48`），四角是**正圆**
- 那 10 个 Bézier 控制点**只用于 `cubicTo` 画轮廓路径**
- **轮廓与折射用的 SDF 在源码层面是脱节的两套东西**

所以「Bézier 控制点 → 距离场」这段代码**在仓库里不存在**，
不可能从源码推出来。

### 1.3 Kyant 的真实做法是预烘焙贴图

唯一把 SDF 当距离场用的是 `clock_sdf.webp`。其 shader 全文在
`catalog/utils/SdfShader.kt:35-75`，解码式：

```glsl
half4 v = sdfTex.eval(p);
float sd = v.r * 2.0 - 1.0;          // R = 有符号距离
v.a = smoothstep(0.5, 1.0, v.a);
if (v.a < 1.0) { sd = 0.0; }
float2 normal = normalize(v.gb * 2.0 - 1.0);   // GB = 边界最近点外法线
float intensity = circleMap(1.0 - min(1.0, -sd * 1.5));
float2 refractedCoord = coord - intensity * refractionHeight * normal;
```

该贴图已被逐像素解码（VP8L 无损），反推的烘焙规格：

| 通道 | 内容 | 公式 |
| --- | --- | --- |
| R | 有符号距离 | `clamp(round(128 − 2.36·d_in), 0, 128)` |
| G | 外法线 x | `127.5 + 127.5·n.x` |
| B | 外法线 y | `127.5 + 127.5·n.y` |
| A | 向外覆盖度 | `clamp(round(255 − 18.4·d_out), 0, 255)` |

## 二、实现

### 2.1 共享轮廓生成器

`build/recon/squircle_path.h` —— 从已验证的 `ccrr_fill.cpp` 抽出，
供烘焙器与其他工具复用。内含：

```text
controlPoints()        解三次/四次方程得 10 个 Bézier 控制点
buildPath()            四角 + 直线段 + close() 组成完整轮廓
maxRadiusFor()         定义域上限 3·min(W,H)/10
signedArea()           鞋带面积
windingNumber()        绕数
distanceToOutline()    到轮廓的最近距离
signedDistance()       有符号距离（符号由绕数定）
```

### 2.2 烘焙器

`build/recon/sq_bake2.cpp`：

```powershell
sq_bake2.exe 620 900 144 build\recon\squircle_sdf.h 6.0
#            宽  高  半径 输出头文件             编码斜率
```

输出与面板像素 1:1 的 8 位掩膜：

```text
R = clamp(128 + 6.0 * sd, 0, 255)      sd 单位像素，正 = 面板内
```

编码斜率 6.0 的取舍：圆角半径 144px，需要角部有足够精度（每像素约 6 级），
同时边缘外侧保留约 21px 过渡带（`128/6 ≈ 21.3`），够透镜与模糊用。

### 2.3 用绕数而不是射线法定符号

本构造在角与直线段衔接处会**重复遍历**一小段边（实测底部一带单行交点数
可达 6）。射线奇偶法在这种近重合交点上会抖动 ——
实测有 **52 个像素**（占 0.009%）两种判定结论相反。
绕数法对自重叠轮廓是鲁棒的，所以用它定符号。

## 三、修掉的两个 bug（这一段是本节最有价值的部分）

第一次烘焙出来的掩膜**底部有两条斜穿的裂缝**，面积核对偏差 **21.88%**。
根因有两个，都是我从子代理的报告**文字**里抄错/漏抄的：

### 3.1 四角表的 `rev` 标志被弄反

我最初抽取的共享头文件里，四角表写的是：

| 角 | rev（错误版） |
| --- | --- |
| 右上 | false |
| 右下 | **false** |
| 左下 | **true** |
| 左上 | true |

而 `ccrr_fill.cpp` 里经数值验证的正确值是：

| 角 | 基准 | x | y | rev（正确） | 源码行 |
| --- | --- | --- | --- | --- | --- |
| 右上 | (w-r, 0) | + | + | **false** | 111-128 |
| 右下 | (w-r, h) | + | − | **true** | 130-147 |
| 左下 | (r, h) | − | − | **false** | 149-166 |
| 左上 | (r, 0) | − | + | **true** | 168-185 |

**为什么这组值必须严格照抄源码**：它是本移植里最反直觉的一处
（见 `docs/SQUIRCLE_PATH_FINDINGS.md` 的 8.x 节），而且
**端点类自检发现不了** —— 反转一段 cubic 走过的是同一组点，只是方向相反：
角形状、端点坐标集合、包围盒、闭合距离**全都不变**。
被破坏的是「角与角之间的直线段方向」，表现为斜穿面板内部的裂缝。

**判定依据**：`ccrr_fill.cpp` 的 `buildKotlinRef()` 是源码逐行转写，
`buildPath()` 是机械化版本，两者的逐点比对在真机与本机都报告
「完全一致」，且该结论对 `rev` 的敏感性已被 `legacy` 开关（复现历史 bug）
验证过。所以**以代码为准**。

**教训**：移植这类「已数值验证」的代码时必须**整块复制**，
不要按描述文字重新实现，也不要"简化"。
描述用于理解，代码用于复用。本次调试中这条教训出现了三次
（`rev` 表、`String8W` 缓冲区偏移、`StrongPointer` 模板形态）。

### 3.2 漏了最后的 `close()`

源码 `RoundedRectangleOutline.kt:187` 有一个 `close()`，
即一条回到子路径起点的直线。漏掉它同样会在底边留下缝。

### 修复后的验证

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 鞋带面积 vs 掩膜内部 | **21.88%** 偏差 | **0.015%** 偏差 |
| 退化（零长）边 | 2 条 | 1 条 |
| 轮廓点数 | 340 | 337 |
| 掩膜形状 | 底部有两条对角裂缝 | 完整圆角矩形 |
| 中心 / 四角 / 边中点检查 | 通过 | 通过 |

掩膜已用 `read_image` 看图确认：二值图是干净的圆角矩形，
灰度图显示正确的距离梯度（角部有连续渐变）。

接入方式（下一步）：

1. 把掩膜上传成 `GL_R8` 纹理，线性过滤
2. 在 panel fragment shader 里按面板局部坐标采样
3. 用 `sd` 替换 `boxMetric` 的圆角部分（**只替换角部**，
   直边段仍用原逻辑，避免影响边缘光与折射）
4. 可选：按 Kyant 的 GB 通道规格补上法线，用于折射

**为什么现在没接**：接入需要改 shader 源码，而 shader 是逐字嵌入的
（`ytbl_shaders_embedded.h` 由脚本从 `Shaders.cpp` 生成）。
改它意味着要在生成流程里插入改动，这是个需要仔细设计的步骤 ——
贸然改动会破坏「shader 与上游逐字一致」这个已经建立的性质。
建议单独一轮做，并在本机 GPU 回归里加一条「曲率剖面」检查
（圆弧 = 常数曲率 vs squircle 从 0 平滑升到 1/r）。

## 五、当前配方里的圆角半径需要注意

烘焙用的半径是 **144px**（`DIALOG_CLOSE_RADIUS_DP = 48dp × density 3.0`）。
而定义域上限是 `3·min(W,H)/10`：

| 面板 | 上限 | 144 是否安全 |
| --- | --- | --- |
| 620×900 | 186 | ✅ |
| 620×620 | 186 | ✅ |
| 400×400 | 120 | ❌ 会四角重叠 |

所以**如果面板尺寸变了，半径与 SDF 都要重烘**。
`sq_bake2.exe` 会在半径超限时直接报错退出，不会静默产出错形状。
